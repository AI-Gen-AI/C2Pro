# #1274 — Platform budget table (read-only draft; no runtime enablement)

- **Owner:** only the immutable Clerk user ID in the *single-entry* server-side PLATFORM_OPERATOR_USER_IDS list; PLUS verified Clerk operator org via existing require_platform_operator, deny-only contamination lookup, and exact method/route authentication registry.
- **API:** GET /api/v1/platform/budgets?query=&limit=&offset=; never use customer-tenant roles, org_role, email, X-Tenant-ID, or client-provided tenant IDs.
- **Source:** public.tenants and TENANT-only row in n4_budget_buckets for UTC month. Tenant and bucket spent/reserved are alternative accounting projections and are never added together. A missing TENANT bucket is labelled NO_TENANT_BUCKET; divergence labelled COUNTERS_DIVERGED. Neither state authorises spending.
- **Runtime:** PLATFORM_BUDGET_READ_DATABASE_URL is mandatory for the *read endpoint*, defaults unset; no fallback to application DATABASE_URL or existing DLQ ADMIN_OPS_DATABASE_URL. Unset/invalid restricted capability => generic 503, no data.
- **Database privileges:** require independently provisioned, reviewed and tested c2pro_platform_budget_reader NOLOGIN capability + unique login with only column-scoped SELECT on tenants (id, name, slug, is_active, ai_budget_monthly, ai_spend_current, ai_spend_reserved_usd, updated_at) and n4_budget_buckets (tenant_id, scope_kind, scope_id, period_key, cap_usd, spent_usd, reserved_usd). NO BYPASSRLS/SUPERUSER/CREATE/UPDATE/INSERT/DELETE; RLS cross-tenant grant scoped to only this capability by independent reviewed policy. No persistent DB role/grants/credentials installed in this PR. Existing C2.5 DLQ capability cannot access these tables.
- **Schema dependency:** main currently lacks the N4 budget buckets implementation from #1270. Merge/deploy of this draft cannot be approved until the exact active schema, RLS policies, and capability are independently reconciled. 503 if schema/capability unavailable. No changes to #1270 or TENANT USD 5 limit.
- **Security review gate:** real disposable PG proof of selected columns and DENY on documents, reviews, source blobs, non-budget tenant columns, mutations, schema/database CREATE, role escalation, tenant-admin access, operator-org membership-only access, forged claims, absent owner allowlist, revoked owner, cross-tenant IDOR, and CORS/CSRF. Tests currently in this draft are *unit-level only* and not a replacement for the PG/HTTP security gate.
- **Later edit proposal only:** separate PR/API PATCH route after SECURITY GO; mandatory reason, validated Decimal, cap >= spent+reserved+UNKNOWN held liability, tenant+bucket locked in one transaction, compare-and-swap expected version, owner platform identity audit event with before/after/period/timestamp; no writes or mutable controls in current draft.
- **Operational:** no deploy to UAT/prod, no budget writes, no N4/N12, no HITL, no change to SEC-04. Keep budget control in CostController/transactional ledger; this screen is observational only.
